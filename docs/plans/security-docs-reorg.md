# Security Documentation Reorganization

**Status:** Not started. A manual multi-session plan, not formatted for AI Session Handler.

Delete the completed `security-hardening-*` plans and the security review documents in
`docs/research/`. Move anything still useful into its long-term home first:

- open work goes into `docs/issues/`, with the context written into the issue instead of linked;
- durable decisions go into new ADRs in `docs/decisions/`;
- runtime facts, accepted risks and deployment requirements go into the owning live docs.

Nothing is deleted until every reference to it has been replaced.

## How to run this plan

- Each session runs one phase. Start by reading this plan and the **Ledger**. Read only the
  sources that phase lists. Do not load whole large documents when an outline and targeted
  section reads will do. Use `rg -n '^#{1,3} '` for outlines and `sed -n 'A,Bp'` for sections.
- End each session by updating the phase status and the Ledger in this file. Then stop.
- Do not delete source documents before Phase 7. Earlier phases only add content and repoint
  links, so the tree stays consistent if a session ends early.
- ADRs are dated records of decisions made at a point in time. Create new ADRs, but never edit
  existing ones, including the 001–008 records and any ADR finished in an earlier phase of this
  plan. When a new ADR supersedes part of an older one (for example hashed keys or the `__Host-`
  cookie versus 006/007), say so in the new ADR's Context and References only. Do not edit
  anything in `docs/archive/`.
- When editing a sibling repository's docs, follow that repository's `AGENTS.md`. Change
  documentation only, never service code.
- No git write operations.
